# Cloudflare D1 Rules

D1 is the single source of truth for this template. The `LiveCounter` Durable
Object caches and broadcasts counts; it never writes D1. Its notifications say
*that* a signature was stored, never that the total is one higher — it answers
them by re-reading D1, which is what makes a cold-start rebuild and a dropped
notification both harmless.

## Access

- One accessor, `getDb(binding)` in `src/db/setup.ts`, wraps the binding with
  Drizzle's D1 driver. It is the only module that imports a driver —
  `src/db/driver-boundary.test.ts` enforces that.
- **Pass the binding in.** D1 is a binding, not a connection: there is no
  handshake to amortise and no pool to keep warm, so there is no singleton and
  no `initDatabase()`. Passing it explicitly is also what lets a test hand a
  query its own isolated database.

```ts
// Hono handler — the binding is on the request context
const counts = await readSignatureCounts(c.env.DB)

// TanStack server function — no request context, so read the isolate's env
import { env } from 'cloudflare:workers'
export const fetchSignatureCount = createServerFn({ method: 'GET' }).handler(async () => {
  const { total } = await readSignatureCounts(env.DB)
  return total
})

// Durable Object — the bindings are on the object, from its constructor
const counts = await readSignatureCounts(this.env.DB)
```

- Never reach for `cloudflare:workers` from a file a browser bundle can import.
  Route loaders run on the client too — put the read in a server function.

## Errors

- Drizzle rethrows driver errors with `Failed query: <sql>` as the message and
  the real error on `cause`. Log `rootCauseMessage(err)` from `src/core/errors.ts`,
  never `err.message`.
- SQLite reports a duplicate in the message rather than in a code — use
  `isUniqueViolation(err)`. Checking for an existing row first is not a check
  but a race; the unique index is the only thing that decides.

## Migrations

- Drizzle generates, Wrangler applies: `pnpm db:generate:<env>` writes SQL into
  `src/db/migrations/<env>/`, `pnpm db:migrate:<env>` applies it. Each
  environment's `migrations_dir` in `wrangler.jsonc` must equal its generator's
  `out` — `src/wrangler-config.test.ts` holds those together.
- Dev applies locally (`--local`), staging and production remotely with an
  explicit `--env`. Local setup needs no Cloudflare credentials.
- Never hand-edit a generated migration; change the schema and regenerate.

## Testing

- Real D1, real migrations: a `*.worker.test.ts` calls `resetDatabase()` from
  `src/db/test-support.ts`, which applies the migrations `vitest.config.ts` read
  off disk and empties the tables.
- The pool shares one database across a file's tests, so isolation is something
  each test asks for rather than inherits.
